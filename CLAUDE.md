# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Commands

```bash
pnpm dev           # Start dev server (http://localhost:3000)
pnpm build         # Production build
pnpm start         # Start production server

pnpm prisma db push          # Push schema changes to DB (no migration files)
pnpm prisma generate         # Regenerate Prisma client — run after every schema change (db push no longer does it in Prisma 7; also runs on postinstall)
pnpm prisma studio           # Open Prisma Studio GUI
```

> **Always use `pnpm`** — never npm or yarn.
>
> **Node:** requires ≥ 22.18 (Prisma 7 CLI). `.nvmrc` pins Node 22 — run `nvm use` in `nexus/` first.

## Environment

Create `.env` at `nexus/`:

```
DATABASE_URL="postgresql://postgres:postgres@localhost:5432/nexus?schema=public"
BETTER_AUTH_SECRET=<32-char secret>
BETTER_AUTH_URL=http://localhost:3000
ANTHROPIC_API_KEY=sk-ant-...
NEXT_PUBLIC_APP_URL=http://localhost:3000
FIRECRAWL_API_KEY=fc-...
```

`BETTER_AUTH_URL` and `NEXT_PUBLIC_APP_URL` must match the port the dev server actually runs on (default 3000) — `lib/auth.ts` uses `BETTER_AUTH_URL` for `baseURL` and `trustedOrigins`.

### Local database (Docker)

Development uses a local Postgres 16 container, not the Hostinger VPS (its database is no longer reachable from outside). The container is defined in a sibling project and shared with it:

```bash
cd ~/_DEVELOPMENT/_CLAUDE/_ESP32/panic-button-backend
docker compose up -d postgres        # container: aigentik-postgres, 127.0.0.1:5432, postgres/postgres
```

This app uses its own database `nexus` inside that server (the panic-button project uses `aigentik`). If the `nexus` database does not exist yet:

```bash
docker exec aigentik-postgres psql -U postgres -c 'CREATE DATABASE nexus;'
pnpm prisma db push
```

Data lives in the named volume `panic-button-backend_aigentik_pgdata` and survives container restarts.

## Architecture Overview

### Request flow

```
Browser → Next.js App Router
  → (auth)/* pages            — login/signup (unauthenticated)
  → (app)/* pages             — protected; layout.tsx server-checks session via auth.api.getSession
  → api/auth/[...all]         — Better-Auth handler (toNextJsHandler)
  → api/trpc/[trpc]           — tRPC handler (fetchRequestHandler)
```

### tRPC

- **`lib/trpc/init.ts`** — defines `createTRPCContext` (reads Better-Auth session + injects Prisma), `publicProcedure`, and `protectedProcedure`
- **`lib/trpc/router.ts`** — root `AppRouter` composed of `notes`, `folders`, `tags`, `ai`, `links` sub-routers
- **`lib/trpc/client.tsx`** — client-side `TRPCReactProvider`, exposes `useTRPC` hook (from `@trpc/tanstack-react-query`)
- In client components: `trpc.xxx.queryOptions()` for queries, `trpc.xxx.mutationOptions()` for mutations
- `notes.search` is a **query** (not mutation) — uses Postgres full-text search via raw SQL

### Tiptap editor (`components/editor/`)

- **`Editor.tsx`** — main component; wires all extensions; autosaves with 1 s debounce via `notes.update` mutation
- **`SlashCommandExtension.ts` / `SlashCommandMenu.tsx`** — `/` command palette
- **`WikiLinkExtension.ts` / `WikiLinkSuggestionExtension.ts` / `WikiLinkNodeView.tsx`** — `[[Note Title]]` linking; stores `data-wiki-link="<noteId>"` in HTML
- **`AICommandMenu.tsx`** — `Ctrl+J` menu; calls `ai.*` mutations
- **`BacklinksPanel.tsx`** — shows notes whose content contains `data-wiki-link="<currentId>"`
- **`VersionHistoryDialog.tsx`** — lists `NoteVersion` records; content snapshots are saved on every update where content changes
- BubbleMenu comes from `@tiptap/extension-bubble-menu` (separate package, not `@tiptap/react`)
- Table extensions use named imports: `import { Table } from "@tiptap/extension-table"`

### Data model key points (Prisma 7)

- `Folder` is self-referential (`parentId → Folder`) for unlimited nesting
- `Note.content` stores Tiptap HTML; wiki-link IDs are embedded as `data-wiki-link` attributes
- `NoteVersion` is a snapshot table (content only); `notes.versions` query returns up to 50 most recent
- `NoteTag` is an explicit join table (composite PK `[noteId, tagId]`)
- **Prisma 7 layout**: connection URL lives in `prisma.config.ts` (not in `schema.prisma`); the client is generated into `lib/generated/prisma/` (gitignored, regenerated by `postinstall`); `lib/db.ts` imports `PrismaClient` from `@/lib/generated/prisma/client` and connects through `@prisma/adapter-pg` — never import from `@prisma/client` directly
- The `prisma` CLI's npm `latest` tag may point at an 8.x release candidate — stay on the 7.x stable line unless deliberately upgrading

### Auth (Better-Auth v1)

- Config: `lib/auth.ts` (server), `lib/auth-client.ts` (client)
- Session gate: `app/(app)/layout.tsx` — redirects to `/login` if no session
- All tRPC procedures that need auth use `protectedProcedure` (throws `UNAUTHORIZED` if no session)

### AI (`lib/trpc/routers/ai.ts`)

- Model: `claude-sonnet-4-6` via `@anthropic-ai/sdk`
- Procedures: `rewrite`, `summarize`, `continue`, `explain`, `fixCode`, `custom` (all mutations), `chat` (mutation with history array)
- `ai.chat` does full-text note retrieval first, falls back to most recent 6 notes when search returns nothing

### Links library (`lib/links/`, `lib/trpc/routers/links.ts`, `components/links/`)

- Plan and rationale: `docs/plan-links.md`
- Flow: `links.preview` (mutation — it spends a Firecrawl credit) → `lib/links/fetchAndClassify.ts` = `lib/firecrawl.ts` `scrapePage` (markdown + metadata) → `lib/links/classify.ts` (Claude **tool-use** with the category enum in the tool schema, so the result is structurally valid) → editable form → `links.create`
- `lib/links/normalizeUrl.ts` — canonical URL (tracking params, hash, casing, trailing slash stripped) is the value stored in `Link.url` and the per-user uniqueness key (`@@unique([url, userId])`); `preview` checks duplicates **before** scraping
- `Link.category` is a Prisma enum; `lib/links/categories.ts` mirrors it with `LINK_CATEGORY_META` (`Record<LinkCategory, …>` so TS fails if they diverge). Adding a category = schema + `db push` + `generate` + meta entry + icon in `components/links/categoryIcons.ts`
- Classification failure degrades to raw metadata (`classified: false`) rather than failing the fetch; Firecrawl errors map to `TIMEOUT` / `BAD_GATEWAY` / `PRECONDITION_FAILED` (key missing) in the router, and the dialog offers "Add manually"
- Favicons / og:images are stored as URLs and rendered with plain `<img referrerPolicy="no-referrer">` (`LinkFavicon`), not `next/image`
- `firecrawl` SDK bundles zod 3 while the project uses zod 4 — never pass Zod schemas to the SDK
- Client invalidation after create/update/delete: `queryClient.invalidateQueries(trpc.links.pathFilter())`

### Sidebar & navigation (`components/sidebar/`)

- **`Sidebar.tsx`** — collapsible; sections: Favorites, Recents, Folders, Tags, Trash
- **`FolderTree.tsx`** — recursive folder rendering with drag-and-drop ordering
- **`CommandPalette.tsx`** — `Ctrl+K` quick switcher backed by `notes.search` (+ a "Links" group from `links.list` and an "Add link" action → `/links?add=1`)
- **`/links`** page (`app/(app)/links/page.tsx`) — reachable from the sidebar footer; grid of `LinkCard`s with `CategoryFilter` chips and search
- **`GraphView.tsx`** — D3 force-directed graph using `notes.graph` (nodes = notes, links = wiki-link edges)
- **`ChatWidget.tsx`** — floating chat panel backed by `ai.chat`

## Key Conventions

- `@/` path alias maps to `nexus/` root (configured in `tsconfig.json`)
- shadcn/ui components live in `components/ui/`; add new ones via `pnpm dlx shadcn add <component>`
- Tailwind CSS v4 — no `tailwind.config.js`; configuration is in `app/globals.css` via CSS variables
- Zod v4 is used for all tRPC input validation (note: `z.string().min(1)` syntax is unchanged from v3)
